# 리깅 · 애니메이션 파이프라인 (v2)

대상 파일: `finger-sports-day-v2.html` (v1 `finger-sports-day-demo.html`은 건드리지 않음)

## 1. 기존 구조 분석 (실제 코드 기준)

요청서가 전제한 구조와 이 프로젝트의 실제 구조가 다르다. 아래는 코드를 확인한 결과다.

| 요청서의 전제 | 실제 코드 |
|---|---|
| GLB/GLTF 3D 모델 로딩 | 없음. 사용자가 그린 2D 그림(또는 사진)을 200×200 분석판으로 옮겨 실루엣을 만들고, 그 위에 격자 메시를 직접 생성한다(`buildSkin`). 앞·뒷면 + 옆면, 두꺼운 곳일수록 볼록 |
| `SkinnedMesh` · `Skeleton` · `Bone` | 사용하지 않음. 일반 `Mesh`의 정점을 CPU에서 직접 계산하는 선형 블렌드 스키닝(`CharMesh.update`). 정점마다 뼈 2개 + 가중치 1개 |
| 본 계층 | 관절 13개(머리·목·골반·어깨/팔꿈치/손 ×2·무릎/발 ×2)와 뼈 10개. 계층은 암묵적: 골반이 루트, 몸통 → 머리/위팔 → 아래팔, 골반 → 허벅지 → 정강이 |
| 본 position/rotation/scale | 뼈마다 평면 회전 + 이동만 사용. 스케일은 쓰지 않는다(측정 결과 뼈 길이 변화 0%) |
| 애니메이션 재생 · 리타게팅 | 키프레임 애니메이션 없음. 매 틱 자세 함수(`runPose`)가 관절 위치를 절차적으로 만든다. 그래서 리타게팅 문제는 "자세 함수가 체형을 고려하느냐"로 바뀐다 |
| MediaPipe Pose로 사람 관절 → 캐릭터 | MediaPipe **Hands**(손). 검지·중지 교대 → 걸음 입력, 손 튕기기 → 점프, 엄지·검지 집기 → 활 당기기. 사람 관절을 캐릭터에 복사하지 않는다 |

입력 흐름은 이미 요청서 7장의 구조와 같다.

```
MediaPipe Hands ─┐
키보드 · 터치   ─┴→ 걸음 이벤트(inputQueue) → 고정 60틱 시뮬레이션(속도 · 균형 · 박자)
                     → 체형별 컨트롤러 runPose(model, 박자, 세기, 기울기) → 관절 13개
                     → CharMesh.update(스키닝) → three.js 렌더
```

## 2. 찌그러짐의 실제 원인 (측정)

달리기 한 주기 8장면에서 앞면 삼각형의 넓이 변화를 쟀다. "심한 변형" = 넓이가 30% 넘게 늘거나 준 삼각형 비율.

수정 전 측정값:

| 그림 | 심한 변형 | 평균 넓이 변형 | 머리 형태 오차 | 뼈 길이 변화 |
|---|---|---|---|---|
| 막대 인간 | 6.0% | 5.5% | 0.0% | 0.0% |
| 곰돌이 | 25.6% | 30.5% | 0.0% | 0.0% |
| 로봇 | 24.3% | 28.5% | 0.0% | 0.0% |
| 큰머리 고양이형 | 16.2% | 21.8% | 0.0% | 0.0% |

요청서의 8가지 후보를 하나씩 확인한 결과:

1. **Rest Pose 불일치 — 핵심 원인.** 기존 `runPose`는 팔다리 각도를 "바로 아래"를 기준으로 한 절대각으로 정했다. 막대 인간은 원래 팔다리가 아래로 향하니 문제가 없지만, 팔을 옆으로 그린 큰머리 캐릭터는 달릴 때마다 팔이 그린 자세에서 **평균 95°, 최대 149°**(아래팔 최대 165°) 돌아갔다. 다리도 평균 31~48°, 최대 96°.
2. **스키닝 가중치 — 두 번째 원인.** 정점의 25~43%가 두 뼈에 섞여 있었고, 팔다리 정점 중 6~7%는 어깨·골반보다 몸통 안쪽에 있었다. 큰 각도로 도는 뼈와 섞인 몸통 살이 끌려가며 접혔다.
3. 관절 위치 — 이전 수정(목 절단선, 손 고르기, 붙은 두 발)에서 고쳤다. 남은 문제 아님.
4. 뼈 길이 · 스케일 — 해당 없음. 측정 0%(스케일을 쓰지 않음).
5. 모델과 애니메이션의 스켈레톤 불일치 — 해당 없음. 자세 함수와 메시가 같은 13관절을 쓴다.
6. 중복 Transform — 없음. 기본 자세로 스키닝하면 정점 이동 0mm.
7. 회전축 불일치 — 해당 없음. 모든 회전이 그림 평면의 한 축이다.
8. 머리와 몸통 연결 — 이전 수정(목 절단선 위 = 머리 영역, 통째로 머리 뼈)에서 고쳤다. 머리 형태 오차 0%.

## 3. 수정 내용

모두 `finger-sports-day-v2.html` 안에서.

- **체형 판단 `classifyRig`**: 몸 두께(키 대비), 머리 높이·넓이 비율, 테두리 중 곧은 직선 비율로 `stick` / `human` / `cartoon` / `rigid`를 고른다. 판단 이유를 화면에 보여주고, 사용자가 "움직임 방식"에서 바꿀 수 있다.
- **체형별 컨트롤러 `runPose` → `runPoseStick` / `runPoseRel`**
  - 막대형: 기존 함수 그대로(이름만 바꿈). 같은 그림으로 이전 코드와 관절 · 정점 좌표가 소수점 9자리까지 같음을 확인했다.
  - 나머지: **그린 자세를 기준으로 한 상대 회전**. 각 뼈를 rest 벡터에서 회전만 시키므로 길이와 비율이 그대로 유지된다. 바닥 맞추기는 더 낮은 발을 원래 서 있던 높이에 둔다.
  - 팔은 **앞뒤로** 흔든다: 그림 평면 안에서 돌리면 옆으로 뻗은 팔이 위아래로 퍼덕이므로, 위팔 방향에 수직인 평면 안 축을 중심으로 평면 밖(화면 쪽 · 안쪽)으로 돌린다(`CharMesh.updateSwing`). 팔꿈치 굽힘도 같은 방식. 막대형은 기존대로 팔이 달리는 방향으로 흔들린다.
  - 변형 검사의 삼각형 넓이는 3D로 잰다(평면 밖으로 돌린 팔이 넓이 감소로 잘못 잡히지 않게).
- **체형별 가중치 `boneFields(ex, mode)`**
  - `soft`(막대형): 기존 그대로.
  - `trunk`(사람형 · 큰머리형): 어깨·골반보다 몸통 쪽에 있는 살은 몸통에 고정, 섞임 경계를 더 좁게(거리 지수 3 → 4).
  - `hard`(부품형): 정점마다 뼈 하나만. 부품끼리 섞여 휘지 않는다.
- **팔다리 굵기 보정 `limbFatness`**: 길이 대비 두께가 큰 팔다리는 팔꿈치·무릎 굽힘을 줄인다(곰돌이 심한 변형 11.5% → 4.9%).
- **체형별 보폭**: 박자 = 속도 ÷ 보폭, 보폭은 다리 길이 × 흔드는 각도로 계산하고, 체형별 최대 박자로 제한한다. 막대형은 기존 식(보폭 2.6m) 그대로.
- **스키닝 갱신 최적화**: 매 프레임 생기던 `forEach` 클로저를 `for` 반복으로 바꿨다. 메시는 변환할 때 한 번만 만들고, 프레임마다 정점 좌표만 갱신한다.
- **개발자 도구**(변환 화면 › "개발자 도구 · 리깅 검사"): 뼈대 선 표시(SkeletonHelper 역할), 기본 자세 / 달리기 테스트 / 일시정지, 속도 슬라이더(0~11m/s), 뼈 목록 · 부모 · 길이 · 쉬는 각 · 뼈별 정점 수 · 임시 뼈 표시, 섞인 정점 비율, 변형 검사(넓이 변형 · 머리 형태 · 뼈 길이 · 프레임당 계산 시간). 콘솔에 `[리깅]` 그룹으로 표와 자동 판단 근거를 남긴다.

## 7. 자동화 가능한 범위 / 사람 손이 필요한 부분

자동:
- 2D 그림 · 사진 → 실루엣 → 두께 → 가운데 선 → 끝점 → 관절 13개 → 머리 영역 → 가중치 → 도톰한 메시
- 체형 판단과 컨트롤러 · 가중치 선택, 변형 품질 검사

사람 손이 필요한 경우:
- 끝점이 틀렸을 때: 변환 화면에서 머리 · 손 · 발 다섯 곳 찍기, 관절 끌기
- 체형 판단이 틀렸을 때: "움직임 방식"에서 직접 선택
- 사람형이 아닌 그림: 현재는 사람형 뼈대에 끼워 맞추는 수밖에 없음

## 8. 앞으로 GLB/GLTF 3D 캐릭터를 받을 때 (설계)

지금 코드는 2D 그림 전용이다. AI로 생성한 3D 캐릭터(GLB)를 받으려면 아래 단계가 새로 필요하다. 이 문서의 컨트롤러 · 체형 판단 개념은 그대로 쓸 수 있다.

```
GLB 업로드 → GLTFLoader → SkinnedMesh/Skeleton 있는지 검사
  ├ 있음: 본 이름 사전(Mixamo · VRM · Rigify 등)으로 13관절에 매핑 → rest pose(T/A) 확인
  │       → 본 스케일 1인지, 가중치 합이 1인지, 머리 정점이 머리 본 하나에 묶였는지 검사
  └ 없음: 자동 리깅 가능 조건 검사(사람형 실루엣, 닫힌 메시, 정면 · 직립, 단위 스케일)
          → 가능: 외부 자동 리깅 후 다시 위 경로 / 불가능: "수동 리깅 필요" 안내
→ 체형 판단(머리 비율 · 팔다리 길이 · 굵기) → 컨트롤러 선택 → 변형 품질 검사 → 게임 적용
```

주의: 정점 가중치가 없는 메시에 Skeleton만 붙이면 움직이지 않는다. 가중치는 반드시 만들어야 한다.

자동 리깅 후보:
- **Mixamo**(Adobe 웹 서비스): 사람형에 강함. 큰 머리 · 짧은 팔다리 카툰은 마커 위치 수동 조정이 필요하고, 공개 API가 없어 자동화가 어렵다.
- **Blender 헤드리스 스크립트**: Rigify 메타리그 또는 직접 만든 본을 맞춘 뒤 "Automatic Weights"(bone heat)로 가중치를 생성한다. 메시가 닫혀 있지 않거나 겹친 면이 있으면 실패하므로 Voxel Remesh 등 사전 정리가 필요하다.
- **연구용 오픈소스**: RigNet(2020, 메시에서 본 · 가중치 예측), UniRig(2025, 다양한 형태용). 서버 GPU가 필요하고 결과 검수가 필요하다.
- **2D 그림 전용**: Meta의 AnimatedDrawings(오픈소스)는 아이 그림에서 관절을 찾는 모델을 쓴다. 지금 규칙 기반 끝점 찾기를 대체할 후보다.

Blender에서 손봐야 하는 흔한 문제(큰머리 카툰 기준):
- **머리 가중치**: 머리 전체 정점 그룹을 머리 본 하나에 1.0으로(Weight Paint). 목 아래 2~3cm만 몸통과 섞는다.
- **짧은 팔다리**: 팔꿈치 · 무릎 본을 없애거나, 아래팔 · 정강이 가중치를 위쪽 본과 같게 해서 덩어리가 반으로 접히지 않게 한다.
- **스케일**: Ctrl+A로 Scale을 적용해 오브젝트 · 본 스케일을 1로 만든다(내보낸 뒤 본 스케일이 1이 아니면 애니메이션이 늘어난다).
- **rest pose**: 애니메이션이 가정하는 자세(T 또는 A)와 맞춘다. 본 롤(roll)을 좌우 대칭으로 맞춘다.
- **부품형(로봇)**: 부품마다 정점 그룹 하나에 1.0, 섞지 않는다. 또는 부품을 본의 자식 오브젝트로 붙인다(스키닝 없이 강체).

## 9. 남아 있는 문제

- 큰머리형은 다리가 짧아(키 1.75m로 맞춘 그림에서 다리 0.3~0.5m) 5m/s 넘으면 박자가 최대값에서 멈추고 발이 미끄러진다. 지금은 일부러 종종걸음 상한을 둔 것이다. 해결하려면 속도에 따라 흔드는 폭을 더 키우거나, 게임 속도를 체형에 맞게 낮춰야 한다(게임 밸런스 문제라 손대지 않음).
- 곰돌이(사람형)는 아직 심한 변형이 4.9%로 0이 아니다. 굵은 다리를 골반에서 흔들 때 배 아래 살이 늘어난다.
- 체형 판단 기준값은 예시 4종(막대 · 곰 · 로봇 · 큰머리)으로만 맞췄다. 다른 그림에서는 틀릴 수 있어 화면에서 바꿀 수 있게 했다.
- 옆면 테두리가 2픽셀 격자 때문에 계단처럼 보인다.
- 네발 동물 · 꼬리 · 날개 전용 뼈대가 없다.
- 실제 웹캠으로 F 테스트를 하지 못했다.

## 10. AI 기반 자동 리깅으로 넓히는 방법

1. **끝점 · 관절 찾기**: 지금의 규칙(가장 멀리 튀어나온 곳)을 그림 전용 관절 추정 모델(AnimatedDrawings 계열)로 바꾸고, 규칙 결과는 대체 경로로 남긴다.
2. **사진 오려내기**: 지역 밝기 임계값 대신 분할 모델(예: SAM 계열)로 그림만 오려낸다.
3. **체형 판단**: 지금은 세 가지 수치 + 임계값이다. 사용자가 "움직임 방식"을 바꾼 기록을 모으면, 그 데이터로 판단 기준을 학습시킬 수 있다.
4. **3D 캐릭터**: AI 생성 GLB → (RigNet/UniRig 또는 Blender 스크립트) → 본 이름 매핑 → 같은 체형 판단 · 컨트롤러 · 변형 검사. 변형 검사(넓이 변형 · 머리 형태 · 뼈 길이)는 3D 메시에도 그대로 적용할 수 있어, 자동 리깅 결과를 사람이 보기 전에 걸러내는 품질 게이트로 쓸 수 있다.
